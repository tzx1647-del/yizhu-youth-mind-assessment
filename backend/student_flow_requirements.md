# 学生端交互与测评次数约束 v1.0
日期：2026-10-17｜用户明确确定｜作用范围：正式线上学生端（不立即修改main上的旧v0.3.2b）

## 已确认的用户要求
1. 正式答题页面只有前进操作，不提供“上一题”按钮；也不能通过题号导航返回修改已完成的题目。
2. 页面同时具有“下一题”和“跳过此题”按钮。
3. 学生完成并成功提交一份正式测评后，不允许再次测评（同一已邀请学生/一次有效邀请只能完成一次）。
4. 这些要求属于正式学生端功能约束，不能只靠隐藏按钮；服务端必须保证第3项。

## 开发期建议的精确定义（后续可按用户实际体验调整，不擅改计分）
- “下一题”：当前情境的所有作答节点均已选择选项时推进；未答完整时提示选择或点“跳过此题”。
- “跳过此题”：跳过**当前整个情境**；涉及多个响应节点的情境，各未作答节点按既有规则记为未作答，直接计分节点为0分，验证节点不计分。不将“跳过”当作一个新的计分选项。
- 最后一个情境以“完成测评”替代“下一题”，提交前显示简短不可返回的确认；成功提交后展示原有六步成长结果。
- 网络中断/页面刷新：对尚未成功提交的邀请，可继续**未完成的一次测评**，但不能开启第二份。上线前必须验证中断恢复和重复提交。
- “一次”以服务端有权限的邀请/参与者记录和已完成提交为准；唯一索引、事务及幂等处理共同防止双击、重放和多设备并发重测。客户端本地存储或隐藏“开始”按钮不足以防重测。
- 邀请链接在测评完成后不可再次答题，但家长报告由意竹后台独立审核发送；学生结果的重新查看许可需单独确定，不能因此开放再次答题。
- 页面公开入口不得绕过邀请、监护人同意以及仅模拟数据的开发环境限制。

## 与历史系统的关系
- GitHub main 的v0.3.2b含“上一题”，属既有运行基线，**当前不直接覆盖**。
- 28情境、35节点、正式计分键与六步结果文字均不因此修改。
- 首先在开发分支调整，远程模拟验证通过后版本化发布。
